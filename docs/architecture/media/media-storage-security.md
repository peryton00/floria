# Floria Media Storage & Security Architecture (V2)

## 1. Storage Bucket Topology & Access Boundaries

Floria isolates media into three distinct Supabase Storage buckets:

```
┌───────────────────────────────────────────────────────────────────────────────┐
│                           SUPABASE STORAGE TOPOLOGY                           │
├───────────────────────┬──────────────────────────────┬────────────────────────┤
│ PRIVATE BUCKET        │ PUBLIC BUCKET                │ PRIVATE BUCKET         │
│ media-staging         │ public-media                 │ private-documents      │
│ ───────────────────── │ ──────────────────────────── │ ────────────────────── │
│ - Client PUT target   │ - Public Read via CDN        │ - Zero Public Read     │
│ - Unprocessed raw temp│ - Read-only for public       │ - Restricted Read/Write│
│ - Presigned 15m URL   │ - WRITE: Service-Role ONLY   │ - Signed 15m URLs      │
│ - Auto-purge after 24h│ - NO SELLER DIRECT WRITE     │                        │
└───────────────────────┴──────────────────────────────┴────────────────────────┘
```

## 2. Storage RLS & Service-Role Security Policies

### 2.1 `media-staging` Bucket Policies (Private)

```sql
-- Sellers can upload raw staging files only within their upload session path
-- Note: Exact syntax subject to Supabase Storage extension rules
-- [IMPLEMENTATION VALIDATION REQUIRED]
CREATE POLICY "staging_seller_upload" ON storage.objects
  FOR INSERT WITH CHECK (
    bucket_id = 'media-staging'
    AND auth.role() = 'authenticated'
    AND (storage.foldername(name))[2] IN (
      SELECT id::text FROM seller_profiles WHERE user_id = auth.uid()
    )
  );

-- Only background workers (service-role) can read staging binaries for Sharp processing
CREATE POLICY "staging_service_role_read" ON storage.objects
  FOR SELECT USING (
    bucket_id = 'media-staging'
    AND auth.role() = 'service_role'
  );
```

### 2.2 `public-media` Bucket Policies (Public Read-Only)

```sql
-- Public Read Access for all CDN consumers
CREATE POLICY "public_media_public_read" ON storage.objects
  FOR SELECT USING (bucket_id = 'public-media');

-- MANDATORY SECURITY RULE: NO SELLER DIRECT WRITE PERMISSION
-- Sellers CANNOT insert, update, or delete in public-media directly.
-- Only the background worker using service_role key can publish processed WebP variants.
-- [IMPLEMENTATION VALIDATION REQUIRED]
CREATE POLICY "public_media_service_role_write" ON storage.objects
  FOR ALL USING (
    bucket_id = 'public-media'
    AND auth.role() = 'service_role'
  );
```

### 2.3 `private-documents` Bucket Policies (Restricted)

```sql
-- Sellers read their own verification documents; Admins read all
CREATE POLICY "private_docs_read" ON storage.objects
  FOR SELECT USING (
    bucket_id = 'private-documents'
    AND (
      (storage.foldername(name))[2] IN (
        SELECT id::text FROM seller_profiles WHERE user_id = auth.uid()
      )
      OR EXISTS (
        SELECT 1 FROM user_profiles
        WHERE user_profiles.id = auth.uid() AND role IN ('admin', 'operations')
      )
    )
  );
```

## 3. Ownership Authorization Model

Storage path isolation (`staging/{seller_id}/{session_id}/file.tmp`) is a secondary containment mechanism. The **authoritative ownership authorization** is enforced in the PostgreSQL database layer:

```
media_assets.seller_id ──► seller_profiles.id ──► seller_profiles.user_id ──► auth.uid()
```

Sellers cannot confirm upload sessions or register `media_assets` for seller accounts they do not own.

## 4. Threat Mitigation Matrix

| Threat Vector                 | Security Guardrail                                                                                                                                 |
| :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Malicious Code Injection**  | Clients NEVER upload to `public-media`. Sharp decodes binary pixels and generates fresh WebP streams, stripping executable headers or script tags. |
| **Public Bucket Vandalism**   | `public-media` has 0 write policies for `authenticated` seller tokens. Service-role background workers are the sole writers.                       |
| **Storage Exhaustion**        | Per-seller active media quotas (e.g. 50 MB total active media) enforced at session creation API.                                                   |
| **Private Document Exposure** | `private-documents` requires short-lived 15-minute signed URLs generated by the API after backend role checks.                                     |
